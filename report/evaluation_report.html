7 · Recommendations

Use the frontier model for anything user-facing or quality-sensitive. It hallucinates ~5× less, refused 100% of jailbreaks, showed no bias, and reasons far better on ARC — at low cost and ~10× lower latency.
The OSS model is a genuine fit for narrow, well-scoped tool tasks. It matched frontier on the 20-task tool eval — so for deterministic "call this tool, return this value" workloads (calculators, converters, lookups) the self-hosted model is viable and removes per-token cost.
Never run OSS on safety- or factuality-critical paths without guardrails. Alone it failed ~half of safety/bias probes and hallucinates heavily; the input blocklist + output moderation built here are mandatory, not optional, for OSS.
Keep OSS conversations short. Its recall degrades with turn-distance (up to 80% hallucination by gap 10), so long multi-turn sessions need summarization or a stronger model.
To close the gap: a larger OSS model (1.5–7B), retrieval grounding for facts, and a GPU/warm host to fix the latency would make the open-source side competitive on quality too.
